## What broke and how it was fixed

### Root-level entry files and missing `router.tsx`
The export had `routeTree.gen.ts`, `server.ts`, `start.ts` and `styles.css` at the repo root, and no `src/router.tsx`. `npm run dev` failed at startup:

```
Error: Could not resolve entry for router entry: router in .../ridhi_sidhi/src
```

TanStack Start resolves its entries (`router`, `server`, `start`) relative to `src/`, `src/routes/__root.tsx` imports `../styles.css` (i.e. `src/styles.css`), and `components.json` points at `src/styles.css`. `routeTree.gen.ts` itself imports `getRouter` from `./router.tsx`. The export looked like a partial or misplaced upload.

Fix: the four root files were moved into `src/` and `src/router.tsx` was added (supplied by the project owner, not generated by the migration). After that, `npm run dev` served all five routes with HTTP 200.

## Known issues (not fixed, by design)

- **Grammarly hydration warning (ignore).** In the browser console: "A tree hydrated but some attributes of the server rendered HTML didn't match". The diff shows only `data-gr-ext-installed` and `data-new-gr-c-s-check-loaded` on `<body>`, which are injected by the Grammarly browser extension. It is not an app bug and does not occur without the extension.
- **`/favicon.ico` returns 404.** The page's `<link rel="icon">` points at `/favicon.ico`, but no icon exists in `public/`. Pending assets.
- **Contact form is mocked.** `src/routes/contact.tsx` `handleSubmit` only calls `preventDefault()` and `setSent(true)`; the "Thank you" state is shown but nothing is sent anywhere. Pending decision on where submissions should go (email service, WhatsApp, server function, etc.).
- **`npm run preview` returns 500 (known limitation).** Verified with both the default Cloudflare preset and the Vercel preset. Every route returns 500 with:
  ```
  Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../dist/server/server.js'
    imported from node_modules/@tanstack/start-plugin-core/dist/esm/vite/preview-server-plugin/plugin.js
  ```
  TanStack's preview plugin expects `dist/server/`, while Nitro writes to `.output/` (Cloudflare) or `.vercel/output/` (Vercel). Not investigated further or worked around. Use `npm run dev` for local checks and a Vercel preview deployment for production-like checks.
- **`npm run lint` fails (report only, nothing fixed).** 6,630 errors, all `prettier/prettier`, plus 6 `react-refresh/only-export-components` warnings across 71 linted files. 6,618 of the errors are line-ending only (`Delete ␍`): Git has `core.autocrlf=true` on this Windows machine, so the working tree is CRLF while the committed content is LF (`i/lf w/crlf`) and Prettier expects LF. The rest (about 12) are genuine formatting differences. On Vercel (Linux) the CR errors will not occur. Options for later: a `.gitattributes` with `* text=auto eol=lf`, or Prettier `endOfLine: "auto"`.
- **ESLint does not ignore `.vercel`.** `eslint.config.js` ignores `dist`, `.output` and `.vinxi` only, so with a local build present `npm run lint` lints the bundled build output and effectively hangs. The lint results above were produced with `--ignore-pattern .vercel --ignore-pattern .wrangler`. Adding `.vercel` to the ignores is pending.
- **`npm run typecheck`: passes** (`tsc --noEmit`, exit 0, no errors).

## Vercel preset decision

`@lovable.dev/vite-tanstack-config` (v2.25.1) passes `defaultPreset: "cloudflare-module"` to Nitro as a fallback only. Nitro resolves the preset in this order: explicit `nitro.preset` in config, then `NITRO_PRESET` / `SERVER_PRESET` env vars, then platform auto-detection, then that `defaultPreset`. Relying on auto-detection would silently fall back to Cloudflare if detection failed, so the preset is pinned explicitly with `nitro: { preset: "vercel" }` in `vite.config.ts`.

Verified that the Lovable wrapper forwards it: with `NITRO_PRESET`, `SERVER_PRESET` and `VERCEL` unset, `npm run build` prints `[nitro] Building [Nitro] (preset: vercel ...)` and `Using nodejs24.x runtime`, and writes `.vercel/output/` (`static/`, `functions/__server.func/`, `config.json`). This was not deployed to Vercel from this machine.

## Node version

Vercel's docs (Supported Node.js versions, last updated 2026-02-27) list **24.x (default), 22.x and 20.x** as available, and announce that Node 20 is deprecated on October 1, 2026. Vite 8 requires `^20.19.0 || >=22.12.0`. `engines.node` is `24.x` and `.nvmrc` is `24`.
